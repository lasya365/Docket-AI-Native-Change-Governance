Change advisory boards exist to answer one question: what will this break, and who signs. The process rests on an assumption that has quietly stopped being true — that a human can read what changed and reason about it.

An engineer writes three sentences of intent. An agent writes eight hundred lines. The board receives the eight hundred lines. The intent, the retries, the files the agent touched and reverted, and the question of whether any human actually read the result — none of it reaches the record. Teams are approving pull requests that no single person fully understands.

And the highest-risk changes file no record at all

Code is the visible case. The invisible cases are worse, because they alter production behaviour without producing anything CAB recognises as a change.

What changedEffect in productionChange record today
Model version bumpEvery agent behaviour shifts at onceNONE
Prompt or instruction editAgent decisions change silentlyNONE
Knowledge article rewriteRetrieval-grounded answers changeNONE
Tool or permission grantAgent's blast radius widensNONE

A support lead editing a knowledge article changes production agent behaviour with no RFC, no approval and no rollback path. In software delivery that would be an unreviewed push to production. In the agent development lifecycle it is an ordinary Tuesday.

How can a change advisory board make an evidence-based decision about a change that no human authored, on artifacts that produce no reviewable diff?

02 — The idea

Not a new process. The same board, retuned.

Docket does not ask anyone to adopt agent governance. It keeps ITIL change management exactly where it is and changes five things about what reaches the board.

01

New change types

Model bumps, prompt edits, knowledge rewrites and permission grants become first-class change records — the four highest-risk changes that file nothing today.

02

New evidence

The provenance chain is assembled onto the record automatically: intent, agent session, diff, review, verification, deploy.

03

New risk model

Risk derives from what the agent actually did and how much a human actually read — not from a standard / normal / emergency dropdown.

04

New routing

Approvals route by the blast radius of the agent's work, not by which service the ticket happens to name.

05

New rollback

Reverting means reverting an agent version — model, prompt, tools and knowledge together. Nobody versions that today.

03 — The evidence chain

Six hooks, one record.

Each link exists somewhere already. None of them travel together, and none of them reach the person who signs.

CHG-2208 · assembled provenance
INTENTThe PRD or issue this traces to — and what in the diff traces to nothing
SESSIONWhich agent, which model version, what it was asked, what it retried, which files it touched and reverted
DIFFThe pull request, with AI-authored and human-authored lines separated
REVIEWWho read it, how much of it, and how long they spent
VERIFYTests written by whom, and coverage measured on the AI-authored lines specifically
DEPLOYWhat shipped, where, and the rollback path that would actually work

Four signals the chain makes computable

Unattributed change

Code in the diff tracing to no requirement. The agent improvised and nobody noticed.

Review depth

800 lines generated, approved in four minutes. AI lowered the cost of writing code, not of reviewing it.

Untested generation

Coverage on the AI-authored lines, not the file average — which hides them.

Blast radius

Which services and entitlements the generated portion actually touches.

Risk score comes from these four. Above threshold goes to the board with the evidence attached; below it auto-approves. The gate is configuration, not judgement.

04 — Architecture

Assembled, not reconstructed.

Every link in the chain already exists in some system. None of them travel together, and none reach the record where a human signs. Docket collects at the moment work happens rather than trying to piece it together at audit time — expired sessions and lost prompts make later reconstruction impossible.

Where the authority sits

The threshold is configuration, not judgement. It sits between the computed risk and the board, so tightening how much autonomy a team has never means changing how anything reasons. Below the line a change auto-approves with its evidence on file; above it, the board gets the same evidence rather than a summary of it.

Rollback is the piece with no equivalent today. Reverting a commit does not revert an agent — the model version, prompt, tool scope and grounding knowledge have to move together, which means they have to be versioned together in the first place.

06 — Why it's different

Everyone stops at merge.

Provenance taggersMark which lines an AI wrote. Useful, and it never leaves the repository.
Session recordersCapture what the agent did in the layer that ran it — before the commit exists, and it stops there.
Spec-linked toolingTies code to a living specification. Answers what governed generation, not who accepted the risk.
DocketAssembles all of it into the record where a human actually signs for production. That record is a Freshservice object — which is why this is an ITSM problem, not an AppSec one.
07 — Value

What changes for the board.

  • VISIBILITYFour change types that file nothing today become reviewable objects
  • DECISIONSRisk from measured evidence, not a dropdown and a guess
  • SPEEDLow-risk agent changes auto-approve instead of queueing for a weekly meeting
  • ACCOUNTABILITYThe signer can see what they are signing for
  • ROLLBACKAn agent version to revert to, not just a commit

08 — Build

One change, end to end.

"An AI-authored PR reaches CAB, and Docket holds it." One record assembled from real hooks, one risk model, one held decision. Everything outside that path is mocked deliberately and labelled as mocked.
